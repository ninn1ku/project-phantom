# Спецификация протокола PHANTOM v1 (черновик)

**Дата:** 2026-11-14. **Статус:** черновик для реализации. Независимо
перепроверены только решения, не сама спецификация; кода нет.

Спецификация состоит из трёх нормативных частей. При расхождении с обзорной
архитектурой (`docs/architecture/ARCHITECTURE.md`) действуют они.

| Часть | Документ | Что определяет |
|---|---|---|
| 0 | `RECONCILIATION.md` | Решения по расхождениям между частями 1–3; имеет приоритет над ними |
| 1 | `CRYPTO_PROFILE.md` | Профиль TLS 1.3 (параметры CP-01…CP-30), raw public keys, формат отпечатка, проверки после рукопожатия, обновление ключей, срок жизни соединения, роли ключей |
| 2 | `TRANSPORT_AND_SESSION.md` | Транспорты T1 (QUIC DATAGRAM) и T2 (TLS поверх TCP), кадрирование, управляющие сообщения, активация сеанса, MTU и проба размера, автомат клиента, keepalive, перебор адресов, пересоединение |
| 3 | `../architecture/SYSTEM_AND_LEAK_PROTECTION.md` | Сторож и демон, жизненный цикл kill switch, наборы правил nftables, DNS, локальная сеть, сервер, конфигурация и её подпись |

Связанные документы: модель угроз (`../threat-model/THREAT_MODEL.md`),
стратегия тестирования (`../testing/TEST_STRATEGY.md`), совместимость клиентов
(`../architecture/CLIENT_COMPATIBILITY.md`).

## Версия протокола

Идентификатор — ALPN `phantom/1`. Изменение формата кадров, набора обязательных
сообщений или профиля TLS требует нового идентификатора; сервер может
поддерживать несколько версий одновременно.

## Условные обозначения

MUST, MUST NOT, SHOULD, MAY — по RFC 2119 и RFC 8174. Числа с пометкой
«уточняется измерением» — стартовые значения, а не нормы.
