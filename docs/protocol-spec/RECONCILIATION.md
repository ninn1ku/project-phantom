# Сведение спецификаций: решения по несогласованностям

**Дата:** 2026-11-14. **Автор:** Lead Architect. **Статус:** нормативно; имеет
приоритет над тремя частями спецификации там, где они расходятся. Независимо
не перепроверено.

Три части спецификации писали разные исполнители параллельно. Сведение
(`docs/architecture/ARCHITECTURE.md` v0.3, §14) выявило 16 расхождений; ещё три (N-17…N-19) найдены при выпуске модели угроз 1.0-rc. Ниже —
решение по каждому. Общий принцип: таймеры и формат сообщений определяет
`TRANSPORT_AND_SESSION.md` (TS), политику хоста и сервера —
`SYSTEM_AND_LEAK_PROTECTION.md` (SYS), параметры TLS — `CRYPTO_PROFILE.md` (CP).
Все числа — стартовые и уточняются измерением.

| № | Расхождение | Решение | Что править при реализации |
|---|---|---|---|
| N-1 | Срок жизни соединения: три разных схемы | Действует TS §6: сервер объявляет `lifetime_s` в `Config`, шлёт `GoAway` заранее и закрывает соединение сам; клиент начинает плановую замену раньше со случайным разбросом. CP-21 и SYS §3.12 читаются как ссылка на TS §6. Свойство G4b оценивается по наибольшему возможному сроку из TS §6 | CP-21, SYS §3.12 |
| N-2 | Предел управляющего сообщения: 1024 или 512 байт | 1024 (TS L3) | SYS |
| N-3 | Лимиты до аутентификации | Действуют оба уровня: условие включения Retry — по TS; жёсткие пределы (на источник и общий) — по SYS. Агрегация источника: /32 для IPv4, /64 для IPv6 | TS §5.7 |
| N-4 | Очередь к клиенту | TS: 64 КиБ с отбрасыванием головы очереди. Основание: свежие пакеты полезнее, а внутренний TCP раньше видит потерю. Выбор подлежит измерению на этапе I9 | SYS |
| N-5 | Kill switch в состоянии `Disconnected` | Действует SYS: состояние kill switch хранит сторож и меняют только команды пользователя; состояние автомата его не определяет. `Disconnected` может сопровождаться `enforcing` (например, после загрузки до подключения). `off` наступает только по явной команде отключения | TS §7.1 |
| N-6 | Истёкшая конфигурация | Переход в `Halted(Config)`; kill switch остаётся `enforcing`; срок льготного периода — SYS §1.8 | SYS |
| N-7 | Номер G17 занят дважды | G17 — сокрытие идентичности клиента от сети (CP §3.2). G18 — минимальность журналов сервера (SYS, S-14) | SYS, модель угроз |
| N-8 | Число закреплённых ключей сервера | Для каждого сервера в подписанной конфигурации клиента — список от 1 до 4 отпечатков. Смена ключа: добавить новый отпечаток → перевести сервер на новый ключ → убрать старый. Ключи серверов независимы | CP §3.4, тест T-G02-07 |
| N-9 | Проверка `Config` | Подписанная конфигурация клиента MUST задавать внутренние адреса, DNS и MTU. `Config` сервера MUST совпадать с ними точно; расхождение — `CONFIG_MISMATCH`. `keepalive_ms` и `lifetime_s` — в диапазонах TS §5.4 | TS §5.4, тест T-G15-08 |
| N-10 | Внешний ICMP | Действует TS (правило M6): внешний ICMP не влияет на выбор транспорта и на размер пакетов T1. Утверждение SYS §1.7 относится только к T2, где ядро может уменьшить MSS по поддельному сообщению: это деградация, а не переключение, записывается как остаточный риск | SYS §1.7 |
| N-11 | SNI | В MVP расширение SNI не отправляется (`enable_sni = false`) независимо от того, задан сервер адресом или именем: verifier имя не использует. Отсутствие SNI — наблюдаемый признак, он входит в перечень O1–O20 | CP-27, TS |
| N-12 | Реакция T2 на отфильтрованный ClientHello | Стандартное поведение библиотеки: TLS alert и закрытие. Молчаливое закрытие не используется: «молчащий» порт сам является отличительным признаком (исследование 05) | CP §5 п. 8 |
| N-13 | Журнал и второе устройство с тем же ключом | Событие вытеснения активного соединения, не инициированного самим клиентом, пишется на уровне предупреждения: отпечаток ключа и время, без адресов. Перечень событий S-14 дополняется им | SYS (S-14) |
| N-14 | DNS без systemd-resolved | Действует SYS: поддерживается управление `resolv.conf` с восстановлением при отключении | тест T-G09-06 |
| N-15 | Стратегия тестирования написана по архитектуре v0.2 | До начала этапа I1 матрица тестов приводится к спецификации: новые состояния автомата (TS §7.1), сторож вместо «демона» как владелец таблицы, инвариант размера датаграммы `≥ 1 + MTU_TUN`, гарантии G17 и G18, решения этого документа. Это обязательная задача этапа I1 | TEST_STRATEGY §2 |
| N-16 | Хранение `last_seq` | Сервер хранит `last_seq` для ключа в памяти; при перечитывании списка ключей не сбрасывает; при перезапуске сервера начинает с нуля. Сообщение `Activate` передаётся внутри аутентифицированного соединения, поэтому обнуление не даёт постороннему возможности повтора | TS §5.5 |
| N-17 | Перебор адресов сервера: TS §8.1 пробует следующий адрес через 2 с и до 4 параллельно; модель угроз (M-08, требование R-5) требует ограничить раскрытие запасных адресов | Адреса перебираются **последовательно**: следующий адрес пробуется только после того, как на текущем завершился неудачей полный цикл попыток обоих транспортов. Параллельных попыток к разным адресам нет. Запасные адреса не проверяются, пока основной работает. Предел новых адресов, раскрываемых в одной сети за час, — параметр конфигурации; стартовое значение 2, утверждает владелец | TS §8.1 |
| N-18 | Повтор попыток: backoff в TS начинается с 1 с, а опубликованные окна остаточной блокировки длятся десятки и сотни секунд (M-07; исследование 08) | Backoff по TS сохраняется для первых попыток. Дополнительно: после трёх неудач подряд к одной тройке «адрес, порт, транспорт» пауза до следующей попытки к ней же — не меньше 60 с; значение стартовое и уточняется измерением на стенде | TS §7 |
| N-19 | Один отпечаток на весь список адресов (TS) или ключ на сервер (M-16) | Действует N-8: отпечатки задаются для каждого сервера. Общий ключ на все серверы допустим как частный случай конфигурации, но не рекомендуется: компрометация одного сервера тогда затрагивает все | TS §8.1 |
