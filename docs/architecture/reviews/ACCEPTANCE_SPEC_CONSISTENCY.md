**Дата:** 2026-11-14. **Исполнитель:** независимый аудитор фазы 0 (не автор решений, не автор замечаний).
**Фаза:** 0 — архитектурная приёмка без кода. **Статус:** отчёт проверки по документам; ничего не запускалось.

Метки: [Факт: документ §] — текст прочитан в этом репозитории; [Вывод]; [Предположение]; [Не проверено].
Ни одно замечание не переведено в `Verified`: кода и тестов нет, а статус требует прохождения теста и проверки
не автором исправления.

Сокращения документов: **CP** — `docs/protocol-spec/CRYPTO_PROFILE.md`; **TS** —

эталонному Linux-клиенту; **сервер** — только сервер; **снимается**.

## 0. Вердикт

1. **Спецификация как целое внутренне не согласована, и это в первую очередь проблема применения, а не
   решений.** Из 19 решений REC в целевых документах применены полностью — ни одно; частично — 4 (N-5, N-7, N-10,
   N-16); остальные 15 записаны только в REC, из них N-15 — плановая задача [Вывод из §2]. CP, TS и SYS по-прежнему содержат
   исходные противоречащие формулировки, а TM, ARCH и TST ссылаются то на старый, то на новый вариант. Правило
   «побеждает REC» (HO §2) делает это допустимым для чтения, но не для реализации: исполнитель, читающий CP-12, TS
   §8.1 или SYS §3.7, получит отменённое требование.
2. **37 замечаний Medium — число сходится** (C-04…C-10 — 7, S-05…S-16 — 12, S-19 — 1, V-01…V-05 и V-07 — 6,
   M-02…M-12 — 11). Решения есть по всем, кроме остатка **V-03**. По существу достаточны 13, достаточны с
   оговорками 20, недостаточны 4 (V-03, M-07, S-19, S-13 в части автомата) [Вывод из §1]. Ни одно не закрыто.
3. **Три решения REC создают новые проблемы:** N-18 не выполняет измеряемое свойство AV1 модели угроз (60 с против
   окон 180/420 с); N-13 нереализуемо в сформулированном виде (сервер не отличает собственную замену клиента от
   второго устройства); N-17 не определяет «новый адрес» и ломает определение «круга» автомата. N-5 требует ещё
   одного перехода автомата (команда `disconnect` из `Disconnected`).
4. **Переход на Windows-клиент оставляет без нормативной основы 9 из 37 Medium** (S-05, S-06, S-07, S-08, S-09,
   V-07 и части S-14, M-02, M-05): их решения — механизмы Linux (nftables, `phantom-guard`, `skuid`, resolved).
   Нормативной спецификации платформенного слоя Windows нет: SYS §6 содержит одну строку с пометками
   [Не проверено]. Параллельно в приёмке появился черновик `docs/architecture/WINDOWS_CLIENT.md` («не нормативен
   до принятия ADR» [Факт: его заголовок]); этим отчётом он не оценивался. Новое замечание A-SPEC-10 (Medium)
   закрывается принятием нормативного документа и тестами на GW до фазы 4.
5. **Матрица тестов отстаёт от спецификации существенно** (§5: 50 конкретных расхождений), а стенды A–D не
   соответствуют средам NSP §4. Приведение — обязательная первая задача реализации (N-15), до этого ни одну
   строку TST нельзя использовать как критерий закрытия.
6. **Блокирующего для начала фазы 1 (эксперименты) нет.** Для фазы 2 (ядро) нужно: ADR со сведением и правка
   CP/TS/SYS (§7, П-1…П-6), решение V-03 (§4). Для фазы 4 — спецификация Windows (П-7, П-8).

**Особо запрошенные решения — выводы.**

- **N-5** — верно по существу и совпадает с SYS; ломает таблицу переходов TS в одном месте (выход в `off` из
  `Disconnected`). На Windows смысл «единственный путь в `off` — администратор» надо решать заново (A-SPEC-11).
- **N-6** — верно (отказ, а не предупреждение — RV §3), но причина `Config` перегружена; нужна отдельная
  `Halted(ConfigExpired)` и явная фраза «после истечения — только ручной импорт».
- **N-8** — верно; затрагивает формат конфигурации клиента (список серверов, у каждого — адреса и 1…4 отпечатка),
  verifier («любой из списка выбранного сервера»), CP-25 (проверка ролей по всем отпечаткам) и T-G02-07.
- **N-9** — лучшее из решений: `Config` превращается в проверку согласованности и перестаёт быть каналом влияния
  сервера. Осталось определить «точно» (порядок DNS, отсутствующее семейство).
- **N-16** — безопасно при условии, что `Activate` никогда не пересекает границу соединения (CP-15, TLS). Требование
  R-7 о согласовании `last_seq` между серверами следует снять как лишнее.
- **N-17** — верно по направлению (R-5), но без определений «новый адрес», «эпизод», «круг» не реализуемо
  однозначно и не тестируемо; цена доступности требует согласия владельца.
- **N-18** — не выполняет AV1. Варианты для ADR: (а) `P_min` как параметр со стартовым значением не ниже
  наибольшего задокументированного окна K9 (420 с) для тройки, не ответившей ни одним пакетом, — остальные тройки
  (другой транспорт, другой адрес) пробуются без паузы; (б) оставить 60 с и ослабить AV1 в TM с записью причины.
  Выбор — за владельцем; (а) согласуется с R8 §5.4, (б) — нет.

### 3.3. Инвариант MTU `≥ 1 + MTU_TUN`

Арифметика сходится [Вывод: пересчёт TS §2.1 п. 3, §4.2]: `max_size()` при `current_mtu` = 1319 и CID 8 байт —
1319 − (1 + 8 + 4 + 16) − 9 = 1281 = 1 + 1280; на проводе 1310…1313 байт UDP payload, внешний пакет 1338…1341 /
1358…1361 байт; граница `quinn` 1347 / 1367; анти-усиление 3 × 2 × 1319 = 7914 байт (TS §5.7); MSS 1240/1220 (M7)
соответствуют 1280 − 40 и 1280 − 60. Инвариант одинаково записан в TS §0, §2.1 п. 1, M2, T-02, T-13, ARCH §5.2,
§6.1. Расходятся: TST T-S10-01 («`max_packet_size ≥ MTU`»), TST §1.2 и §4 (состояние `Degraded`). Условие «длина CID
8 байт на обеих сторонах» (TS §4.2) не попало в таблицу профиля и в тест T-13 — добавить, иначе смена длины CID
молча нарушит M2.

## 4. Решение для остатка V-03

Исходные данные: RV §2 (утрата `Activated`, `Superseded` без подтверждения, пакеты в паузе, снятие маршрута);
TS §5.4–§5.6, §8.2; ARCH §4; SYS §3.7; REC N-13, N-16. Предложение аудитора — для ADR, не норма. Числа ⟂ —
стартовые.

### 4.1. Параметры

| Имя | Смысл | Старт ⟂ | Ограничение |
|---|---|---|---|
| `T_ACTIVATE` | Клиент ждёт `Activated` после `Activate{s}` | 5 с | ≥ 3·PTO соединения; клиент сам соблюдает лимит активаций сервера, поэтому серверная задержка в норме не возникает |
| `T_DRAIN` | Сервер держит вытесненное соединение открытым и принимает из него пакеты | 2 с (уже в TS §5.5) | ≤ `T_ACTIVATE` |
| `MAX_REJECTS` | `ActivateRejected` подряд на одном соединении | 3 | Затем `Close(PROTOCOL_ERROR)` |
| `N_FOREIGN` / `T_FOREIGN` | Чужие вытеснения до остановки | 3 за 10 мин | — |
| Лимит активаций | Как TS §5.5 (6/мин на ключ) | — | Клиент применяет тот же лимит к себе |

### 4.2. Правила клиента

- **К1.** Не более одного неподтверждённого `Activate` на сервер («ожидаемый `s`»). Следующий — только после
  `Activated`, `ActivateRejected`, закрытия соединения или истечения `T_ACTIVATE`.
- **К2.** Значение `s` резервируется и записывается (`fsync`) до отправки (перенос правила ARCH §4 в TS §5.5).
- **К3.** `Activated{x}`: `x` = ожидаемому — переход на новое соединение; иначе `Close(PROTOCOL_ERROR)`.
- **К4.** `ActivateRejected{x, m}`: `x` = ожидаемому — счётчик := `m` (с записью), повтор `Activate{m}` на том же
  соединении, не более `MAX_REJECTS`; иначе `PROTOCOL_ERROR`.
- **К5.** `Superseded{x}` на активном A при ожидаемом `s` на B и `x = s` — сервер уже переключился на B. Клиент
  перестаёт слать в A. Если B живо — ждёт `Activated` до конца `T_ACTIVATE`; если B потеряно или срок истёк —
  `Reconnecting` **без backoff**, событие не является наблюдением о сети.
- **К6.** `Superseded{x}` без ожидаемого `s` или с `x ≠ s`, а также `Close(SUPERSEDED)` без собственной активации —
  «чужая активация» (второе устройство или украденный ключ, RR9): событие диагностики, `Reconnecting` с backoff;
  `N_FOREIGN` таких событий за `T_FOREIGN` — `Halted(Duplicate)` (новая причина) с сообщением «ключ этого устройства
  используется в другом месте». Иначе два устройства с одним ключом вытесняют друг друга бесконечно.
- **К7.** `T_ACTIVATE` истёк, `Superseded` не приходил: закрыть B (`NO_ERROR`); если A живо — `Connected(T)` с
  повтором по TS §8.2 (5, 10, 20 с); если нет — `Reconnecting`.
- **К8.** Принятое по A после `Superseded` доставляется ещё 2 с (TS §5.4, без изменений).

### 4.3. Правила сервера

- **С1.** `Activate{s}` на кандидате B, `s > last_seq`, квота есть: одним шагом под блокировкой таблицы —
  `last_seq := s`, маршрут → B, B активно, прежнее A — «вытеснено»; затем `Superseded{s}` в A и `Activated{s}` в B.
- **С2.** Квоты нет: в очереди хранится одна последняя пара (B, `s`) на ключ (ARCH §4). При освобождении квоты сервер
  заново проверяет, что B открыто и `s > last_seq`; до этого B остаётся кандидатом, маршрут не меняется.
- **С3.** Вытесненное A: восходящие пакеты принимаются (с проверкой источника по ключу) в течение `T_DRAIN`,
  нисходящие не отправляются; `Activate` на вытесненном соединении — `PROTOCOL_ERROR`. По истечении `T_DRAIN` —
  `Close(SUPERSEDED)`. Повторная активация вытесненного соединения отвергнута как лишний переход ради выигрыша
  одного рукопожатия.
- **С4.** Активное соединение закрыто без замены (любая причина): маршрут снимается сразу; пакеты к внутреннему
  адресу клиента отбрасываются со счётчиком до следующей активации; ICMP процесс не формирует (M5). «Чёрная дыра»
  ограничена временем переподключения клиента, а не idle timeout.
- **С5.** Третий кандидат на ключ — `Close(RESOURCE_LIMIT)` нового соединения; активное не затрагивается (SYS §3.7).
- **С6.** `Activate{s}` на уже активном соединении при `s > last_seq` — `last_seq := s`, `Activated{s}`, маршрут не
  меняется (идемпотентно).
- **С7.** Журнал (вместо N-13): предупреждение по ключу, если за 10 мин ⟂ вытесненное соединение того же ключа
  сменялось активацией из другого соединения, а затем ключ снова активировался с соединения, установленного после
  вытеснения, не менее 3 раз («пинг-понг»); поля — метка оператора, время до минуты, код; без адресов.

### 4.4. Переходы, добавляемые в TS §7.2

| Из | Событие | В | Примечание |
|---|---|---|---|
| `Connecting` | `T_ACTIVATE` истёк | `Connecting` | Соединение закрыто; попытка к этой тройке считается неудачной, не наблюдением |
| `Switching` | `Superseded{s}` своё, новое живо | `Switching` | Старое больше не используется для отправки |
| `Switching` | `Superseded{s}` своё, новое потеряно или `T_ACTIVATE` истёк | `Reconnecting` | Без backoff |
| `Switching` | `T_ACTIVATE` истёк, старое живо | `Connected(T)` | Повтор по TS §8.2 |
| `Connected`, `Suspect`, `Switching` | чужое `Superseded` или `Close(SUPERSEDED)` | `Reconnecting` | С backoff; счётчик К6 |
| любое с соединением | `N_FOREIGN` чужих вытеснений за `T_FOREIGN` | `Halted(Duplicate)` | Выход — команда `connect` |
