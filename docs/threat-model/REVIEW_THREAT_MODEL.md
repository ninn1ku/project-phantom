# Независимая проверка модели угроз v0.2 (поток T1)

**Дата:** 2026-11-14. **Объект:** `docs/threat-model/THREAT_MODEL.md` v0.2. **Сверено с:** `ARCHITECTURE.md` v0.2,
`reviews/REVIEW_SECURITY.md` (S-14, S-18), `reviews/REVIEW_CRYPTO.md` (C-08), `reviews/REVERIFY_HIGH.md`,
`research/05`, `research/07`, `research/08-availability-loss-causes.md`. Проверяющий не автор модели угроз.

## 0. Метод и метки

- Метки: **[Факт]**, **[Вывод]**, **[Предположение]**, **[Не проверено]**. Серьёзность — по шкале
  `SECURITY_FINDINGS.md`.

## 1. Вердикт

Модель честная по тону: необнаружимость не обещается, остаточные риски перечислены, вне рамок названо прямо.
Перевести её в 1.0 сейчас нельзя по трём причинам:

1. **G8 сильнее механизма.** Перепроверка V3 признала исправление S-01 недостаточным (V-06): штатная
   `nftables.service` Debian/Ubuntu стирает таблицу при загрузке, слежение работает только при живом
   демоне, мост L2 обходит `inet forward` (V-07). Формулировка «после перезагрузки (кроме окна RR15)»
   описывает ограниченное окно, а оно неограничено.
2. **Доступность (A7) не имеет ни одного измеряемого утверждения**, а часть рисков доступности из `05` §5.3
   (остаточная блокировка, вызванная третьим лицом; ограничение объёма; перечисление запасных адресов
   вынужденным переключением) в RR не перенесена.
3. **Открыты C-08, S-14, S-18**, и к ним добавились противоречия с ARCHITECTURE v0.2 (DNS-имя сервера,
   0.5-RTT в T1, строка `Disconnected`).

Critical нет. High — одно (M-01, повторяет V-06 на уровне модели).

## 3. Подробности

### 3.1. Активы (M-04, M-05)

Добавить: **A11** постоянное состояние клиента — `seq` (§4), наибольшая принятая версия конфигурации (§9),
флаг `enforcing`, память «транспорт не работает» по сети (§7.1 п. 3); свойства: целостность и доступность —
их утрата запирает клиента (V-02, V-05), подмена снимает защиту. **A12** якорь доверия — открытый ключ
оператора; целостность. **A13** системное время узла; целостность (V-04). **A14** управляющий канал CLI →
демон; подлинность команд (`disconnect` снимает kill switch). **A15** входящая доступность клиента из
локальной сети; доступность и конфиденциальность (S-18). A9 переформулировать: «журналы и состояние
содержат только поля из перечня, со сроком хранения; адреса клиента выключены по умолчанию».

### 3.2. Атакующие (M-06)

- **T11 — атакующий, использующий чужие устройства фильтрации.** Вне пути, подделывает пакеты от имени
  клиента или сервера, вызывает остаточную блокировку тройки или блокировку UDP между произвольными
  хостами. **[Факт]** Zohaib et al. 2025 (полный текст прочитан): механизм QUIC-фильтрации можно обратить на
  блокировку UDP между произвольными хостами. Против: A7. Механизм защиты — только backoff и резервные
  адреса.
- **T4:** добавить «подменяет неаутентифицированное время (NTP) в состоянии `off`»; **T6:** добавить
  «читает файлы состояния с неверными правами».

### 3.3. Границы доверия (M-05, M-17)

B5 пометить «целевая, схема выбирается на этапе 8». Добавить **B6** — рабочее место оператора с ключом
подписи и сервер; **B7** — канал первичной доставки конфигурации и якоря (QR, файл, вручную). Диаграмма §1
должна показывать канал обновлений и оператора.

### 3.4. Гарантии сильнее механизма

- **G8 (M-01).** Предлагаемая формулировка: «В состоянии `enforcing` трафик хоста и маршрутизируемый
  (L3) трафик namespaces не выходит мимо туннеля при работе и при сбое процесса и транспорта. После
  перезагрузки — при условии, что unit восстановления упорядочен после `nftables.service`/`firewalld`
  (V-06); удаление таблицы обнаруживается только при работающем демоне. Не покрыто: мост L2, сеть
  initramfs, ПО с root». Статус до V-06 и V-07 — «не выполняется».
- **G9 (M-02).** Добавить исключение: «кроме разрешения имени сервера, если оно задано именем (ARCH
  §6.2)», и допущение «поддерживаемый резолвер (systemd-resolved)». Тест — включая включённую LAN.
- **G17 для A4 (M-03).** «Идентичность клиента (его сертификат или ключ) не раскрывается T1, T2, T4 и
  T3 без ключа сервера; последующая кража ключа сервера не раскрывает записанную идентичность».
  **[Факт]** RFC 8446 §4.4: Certificate шифруется ключами handshake; E.1: клиент раскрывает идентичность
  только аутентифицированному серверу. Границы: пропадает при дефекте verifier (C-01, V-01); владелец
  любого из закреплённых ключей сервера получает её; известна серверу и T5; содержимое сертификата —
  фиксированный шаблон без имён (C-08). Тест: клиент не отправляет `Certificate` серверу с чужим ключом.
- **G3/G6 (M-12).** Механизм дополнить запретом `quinn::Connecting::into_0rtt` на сервере; тест — сервер
  T1 ничего не отправляет по потокам и DATAGRAM до `Finished` клиента.
- **G15 (M-11).** Допущения: часы в пределах; сохранённое состояние версии не утрачено (иначе — только
  ручная установка, V-05).

### 3.5. Пропущенные угрозы

- **Перечисление запасных адресов (M-08).** Атакующий блокирует основной адрес — клиент по ARCH §7.1 п. 8
  переходит к запасному и раскрывает его; повтор раскрывает все. Защиты нет; смягчение — лимит одного
  нового адреса за эпизод с паузой (`08` §6 R-5).
- **Управляемая диагностика (M-08, M-15).** Атакующий на пути выбирает симптом: поддельный PTB — переход
  на T2 с памятью «до часов»; сброс TCP — `Reconnecting`. RR16 говорит о «ложной диагностике», но не о
  намеренной.
- **Цена PQ-профиля для доступности (M-09).** **[Факт]** RFC 10024 §4.1: доля клиента 1216 байт; RFC 9001
  §4.3: большие key share не помещаются в 1200-байтный Initial. По ARCH §3.1 отката на классическую группу
  нет (G7) — значит, сеть, не пропускающая крупный первый полёт, делает недоступными оба транспорта.
  Насколько это распространено — **[Не проверено]**.
- **Остаточное состояние и повторы (M-07).** Частые повторы к той же тройке продлевают блокировку там,
  где таймер сбрасывается пакетами клиента [05:20]; отсутствие нижней границы паузы — дефект логики, а не
  только риск.

### 3.7. Недооценённые остаточные риски

- **RR1** — добавить, что достаточно одного ClientHello (ALPN, одна группа) или одного зонда (M-19, M-10).
- **RR3** — «смягчается T2» верно для K2 из `08`, но не для отказа на крупном первом полёте (M-09).
- **RR5** — не только производительность: в T2 нет миграции (G16) и проще сброс соединения (M-15).
- **RR16** — дополнить намеренным управлением диагностикой.
- **RR17** — см. M-08.

## 5. Не проверено

- Поведение `webpki` и `firewalld` (наследуется из V3).
- Распространённость отказов middlebox на ClientHello больше одного сегмента или датаграммы.
- Порядок расширений ClientHello `rustls` и итоговый размер — требует захвата на стенде.
- Реакция конкретных фильтров на признаки O1–O20 не устанавливалась и не утверждается.
